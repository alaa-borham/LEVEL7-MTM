# المرحلة الأولى: البترون يُحسب داخل GRAFIS

```
XML من ERP ← LEVEL7 MTM (استلام، تحقق، مراجعات، قواعد الربط) ← قيم X لكل طلب
           ← GRAFIS (نافذة X Values، قيمة لكل طلب باسم البند، مثل 9-53-1_2) ← حساب البترون
           ← ملف GRAFIS الناتج ← LEVEL7 Nesting
```

## ما أصبح مقروءًا من ملف MDL
- **جدول قيم X لكل جزء** (كتلة `(3,part,3,1)`): رقم X، واسمه، والقيمة الافتراضية `_xxxxx_x`، وقيمة كل مقاس. القراءة مطابقة للقطة شاشة نافذة X Values التي أرسلها صاحب المشروع، والمقارنة مثبتة باختبار آلي.
- **الجزء 002 فيه 12 قيمة X:**

| X | الاسم |
|---|---|
| X1 | الطول |
| X2 | — |
| X3 | shoulder--B |
| X4 | down FRONT R |
| X5 | down FRONT L |
| X6 | armhole high--C2 |
| X7 | collar--E1 |
| X8 | front width 1 |
| X9 | chest girth |
| X10 | front width |
| X11 | back width |
| X12 | waist girth--D |

## كشف قيم X لكل طلب
- **الأوامر:** `level7mtm grafis-x 9-53-1_2 --mdl "1-S- alshiaka-2027.mdl"`، أو زر «قيم X لجرافس» في شاشة الاعتماد والإرسال.
- **الملفات الناتجة:** `grafis/<البند>_X.csv` (يفتح في Excel) و`_X.json`.
- **محتوى كل صف:** القيمة من الطلب، ومصدرها، والقاعدة وحالتها، والقيمة الافتراضية في GRAFIS، ونطاق مقاسات GRAFIS القياسية.
- **قيمة X لا يغطيها الطلب** (مثل X8 front width 1): تظهر كتحذير صريح بأن GRAFIS سيستخدم القيمة الافتراضية. لا شيء يُملأ بصمت.

لا يُكتب أي شيء داخل ملف الـMDL. صيغة الملف الذي يستورده GRAFIS في نافذة X Values غير معروفة بعد، فالكشف حاليًا للإدخال في تلك النافذة.

## معنى القيم (قرار صاحب المشروع)

- **قياسات XML نهائية:** هي قياسات المنتج، وتُدخل في متغيرات X كما هي بالقيمة `{M}`، دون إضافة راحة.
- **قيم ملف GRAFIS الأساسي افتراضية:** القيمة الافتراضية `_xxxxx_x` وقيم المقاسات `__HN..` افتراضية فقط، ولا تُستخدم كمرجع لصحة قيمة الطلب. يعرضها الكشف للمقارنة دون تحذير.
